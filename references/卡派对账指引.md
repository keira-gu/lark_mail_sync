# 卡派对账归档指引（gofreight_ap cardispatch）

一句话：拿《服务商明细》Excel，逐个 TK **只读**核对 GoFreight 会计页的应付金额，
把发票 PDF 从 GoFreight 下载归档，结果标注回原 Excel。核对口径 2026-11-19 定稿，
标注 / 归档 / PDF 金额识别口径 2026-11-20 按用户要求修订。

## 红线

1. **对 GoFreight 只读**：只核对金额、下载附件，绝不建立 / 修改 / 删除任何数据。
2. **两段式**：不带 `--yes` 只打印核对计划；用户明确确认后才 `--yes` 执行。
3. **原 Excel 只写三列**：发票金额 / 发票情况 / 对账问题，写前自动备份
   （`<名>.backup-时间戳.xlsx`）；其余列绝不碰。
4. **附件只从 GoFreight 取**：会计页文件中心优先 → 备忘录兜底；
   不从多维表、不从邮箱另拉。

## 一、前置条件

- `.env` 里只需 GoFreight **三样**：`GOFREIGHT_BASE_URL` / `GOFREIGHT_USER` /
  `GOFREIGHT_PASSWORD`（费用代码、供应商映射、防重账本这套建立应付配置都用不到）。
- 本机装有 Chrome 或 Edge；`requirements-gofreight.txt`（playwright + openpyxl）已装；
  PDF 金额识别用的 pypdf 在核心 `requirements.txt` 里，setup.bat 默认已装。
- 输入 Excel 一份，格式同《美国服务商明细.xlsx》（列要求见下）。
- 跑批期间该 GoFreight 账号别在别处登录（单会话互踢，同建立应付）。

## 二、输入：服务商明细 Excel

按**表头模糊匹配**找列（找不到必需列直接报错退出，提示实际表头）：

| 列 | 匹配关键词 | 必需 | 用途 |
|---|---|---|---|
| 服务商名称 | 服务商 | ✅ | 供应商过滤核对 + 归档文件名 |
| 文件编号(TK) | 文件编号 / TK | ✅ | 逐行访问 GoFreight 会计页 |
| 应付金额 | 应付金额 | ✅ | 明细侧金额（核对目标） |
| 发票日期 | 发票日期 / 开票日期 | 可选 | 计划展示 |
| D/C发票号码 | D/C / 发票号码 | 可选 | 单笔时与 GoFreight 发票号交叉校验 |
| 币种 | 币种 | 可选 | 计划展示与不符提示 |

行级规则：

- **TK 列为空的行静默跳过**（小计行 / 空行）。
- TK 有值但服务商名称为空、或应付金额解析不出 → 打印「第 N 行跳过：原因」，
  **不进批次也不静默丢**。
- **负数金额 = 供应商贷项 / 冲减行，属有效对账行**，照常参与核对（合计口径）。
- 只读第一个工作表。
- **文件参数可以整个省略**（v1.5.9）：自动发现最新的《服务商明细》表——当前目录 →
  桌面 → 下载 → 文档（含 OneDrive 重定向）里名字含「服务商明细」的 `.xlsx`，
  **排除** 备份（.backup-）/ 对账结果 / 对账标注 / ~$ 变体，取**最近修改**的一份；
  计划首行 `明细表：…` 明确打印用的是哪份，确认计划时把关。找不到会报错列出目录
  （把表放到桌面/下载/文档任一目录即可）。
- 给了参数则：完整路径直用（最稳，Shift+右键 →「复制文件地址」粘贴）；
  只给文件名时自动定位（精确同名优先、其次名字包含；唯一命中即用，多个候选 /
  找不到会报错列出）。备份 / 对账结果等同名变体不影响精确命中。

## 三、金额核对口径

- 数据源 = 会计页【应付区】表格。会计页表格**没有表头**，代码按实测行特征定位
  （MB/L portlet 内、含「成本(应付)」行）——不猜 portlet 标题；表格异步渲染，
  扫描不到自动重试 3 次。
- **多供应商共 TK 必须按供应商过滤**（2026-11-19 实证：TK-20990011 同柜 8 家各一笔）：
  只合计**本行服务商**的账单，别家的绝不掺进来；该 TK 有账但没本服务商的 → NO_BILL，
  备注注明「另有 N 笔其他供应商账单未计入本行核对」。供应商匹配 = 大写去非字母数字后
  相等或互含。
- **合计核对**：一 TK 多笔应付按合计比（多行摊分属正常），容差 0.01。
- **D/C 号交叉校验**（仅单笔时）：GoFreight 发票号 vs 明细 D/C 号，归一化
  （去非字母数字 + 去 INV 前缀）后相等或互含算匹配（如 INV-28643 vs 28643）；
  不一致只标注「发票号不一致」不判死。
- 状态七态：

| 状态 | 含义 | 附件照下？ |
|---|---|---|
| OK | 金额核对通过 | 下 |
| MISMATCH | GoFreight 合计 ≠ 明细金额（清单标红） | 下 |
| NO_BILL | 该 TK 无本供应商账单（含全是别家的情况） | 下 |
| NO_AMOUNT | 账单行读不到金额 | 下 |
| NO_PDF | 金额过了但两处都无发票附件 | — |
| READ_FAIL | 账单表定位失败（跑 --probe 看结构） | — |
| FAIL | 意外异常（自动截图 runtime-outputs/gofreight/） | — |

单行失败不终止批次；结束汇总各态数量，有 READ_FAIL / FAIL 时命令返回非 0。

## 四、附件来源与下载

**只从 GoFreight 取**，优先级：

1. **shipment 文档页** `/truck/shipment/document/{TK}`——业务传发票就在这里。
   ⚠ 主页「文件(N)」按钮计的是 **MBL 层**，恒为 0，**不可信**（2026-11-19 实证）。
   文件中心混着包装清单 / 船舶证书 / POD，**只认发票样文件名**（含 INV / INVOICE / 发票）；
   整页只有一个 PDF 时无字样也兜底取；多个 PDF 都不发票样 → 不取并在备注注明。
2. **会计页备忘录附件兜底**（memo 链路上传过的发票）。

下载端点 = `/document/download/{id}/`（预览链接把 /preview/ 换 /download/），
每个响应都做 `%PDF` 魔数校验；同 TK 多行（多供应商共票）复用已下载缓存，
不重复访问页面。

## 五、归档口径

- 归档名 = `服务商_执行日期.pdf`（执行日期 = 跑批当天，非发票日期）；
  非法字符清洗；同服务商同天重名自动 `_02` / `_03`（大小写不敏感）。
- **md5 全局内容去重**（2026-11-20 用户口径「不要重复发票」）：同一份发票
  （内容 md5 相同）整个归档目录只存一份，首个归档者的命名生效，后续行
  （含其他供应商共票的行）直接复用。
- 输出目录 `--out`，默认 `D:/卡派发票`；跑前预热目录里已有文件的 md5 索引，
  **重跑安全**（已归档的不重复写）。

## 六、发票金额识别（PDF →「发票金额」列）

原 Excel 的「发票金额」列正是核对目标，标注时填 **PDF 识别出的发票真实金额**
（2026-11-20 用户口径：全覆盖；识别不出置空，不留 GoFreight 金额）：

- pypdf 抽文本层，按标签优先级取数：**Balance Due > Amount Due / Total Due >
  Invoice / Grand / Total Amount > Total > Subtotal**；无任何标签时取全文最大金额
  （卡车行发票常见多行数字，最大 ≈ 总额）。
- 同 TK 多张发票时按**供应商名匹配**定位本行的（供应商名分词 ≥4 字符，全命中或
  过半命中），多张匹配求和；只有一张时不匹配也兜底用。
- 识别不出的原因（进「发票情况」列）：`no_vendor_invoice`=多张里没有一张属于本
  供应商（发票没传）；`no_text`=扫描件无文本层；`unparseable`=匹配到了但读不出金额。

## 七、结果产物（跑完三样）

1. **附件归档目录**（默认 `D:\卡派发票`）：`服务商_当天日期.pdf`，md5 去重。
2. **对账清单** `runtime-outputs/cardispatch/卡派对账清单_时间戳.xlsx`：
   十列（行号 / 服务商 / TK / 币种 / 应付金额(明细) / 发票号(GoFreight) /
   金额(GoFreight) / 核对结果 / 归档文件 / 状态备注），MISMATCH / NO_BILL /
   READ_FAIL / FAIL 行标红。对账以这份为准。
3. **原 Excel 三列标注**（先自动备份；原文件被 Excel 占用时自动落
   `<名>_对账标注.xlsx` 副本，绝不丢结果）：
   - **发票金额** ← PDF 识别金额（识别不出置空）；
   - **发票情况** ← 一句话：金额异常标签（金额不符 / GoFreight无账单 / …）+
     附件情况（已下载N份 / 未找到发票附件）+ 识别情况（未识别原因）；
   - **对账问题** ← 只写问题、通过行留空；优先复用原表自带空尾列（超范围新建列
     在 WPS 里可能不显示），没有空尾列才新建表头。**不加底色**（2026-11-20
     用户口径：问题看列文字，不标红）。

## 八、命令参考

```bash
python_venv/Scripts/python -m gofreight_ap --env-file .env cardispatch                            # 只出计划（自动发现最新明细表）
python_venv/Scripts/python -m gofreight_ap --env-file .env cardispatch --yes                      # 真执行（自动发现）
python_venv/Scripts/python -m gofreight_ap --env-file .env cardispatch 明细表.xlsx --yes          # 指定文件名（自动定位）或完整路径
python_venv/Scripts/python -m gofreight_ap --env-file .env cardispatch --yes --out D:/卡派发票
python_venv/Scripts/python -m gofreight_ap --env-file .env cardispatch --yes --tk TK-20990011 --limit 20
python_venv/Scripts/python -m gofreight_ap --env-file .env cardispatch --probe --tk TK-20990011
```

- `--tk`（可多次）/ `--limit`：缩小本轮范围；**`--invoice` 对 cardispatch 无效**
  （明细侧没有发票号过滤，别用）。
- `--probe --tk TK-x`：dump 该 TK 会计页全部 portlet 表格结构 + 备忘录附件原始字段
  （JSON 打印）。**首次使用前先跑一次定稿控件认知**；READ_FAIL 排查也靠它
  （模式同 memo 2026-11-10 定稿流程）。

## 九、常见问题

| 现象 | 处理 |
|---|---|
| 账单行未定位（READ_FAIL） | 先 `--tk` 单独重跑（表格异步渲染慢）；仍失败 `--probe --tk` dump 结构，对照第三节识别口径看 GoFreight 是否改版 |
| NO_BILL 但业务说录过 | 多供应商共 TK 看备注「另有 N 笔」；MBL 层账单 TK 会计页看不到（同建立应付防重弹窗场景）→ 转人工核对，绝不反向改明细 |
| MISMATCH | 对账清单两列金额直接比，转人工；先确认哪边对，再决定改不改 Excel |
| 未找到发票附件 | 业务在 GoFreight 补传后重跑；归档 md5 去重，已下载的不重复 |
| 发票金额未识别(扫描件) | 人工看归档 PDF 补「发票金额」列，重跑不解决 |
| 中途断了 / 想重跑 | 直接重跑整份：附件去重、清单另落新文件、Excel 先备份再覆盖标注，全部幂等 |
| WorkBuddy 预计要 2 小时 / 跑得很慢 | 旧版（≤v1.5.6）每 TK 固定等待 ~13 秒，或 WorkBuddy 分批跑 | 先 `git pull` 升到 v1.5.7（就绪即走+按 TK 缓存，约 6~10 秒/TK）；话术里加「确认后一口气跑完，不要分批，全部跑完再汇报」；仍慢查本机到 GoFreight 站点的网络延迟 |

## 十、速度口径（v1.5.7 起）

- **就绪即走**：会计页 / 文档页表格一渲染出来就往下走（0.7 秒轮询，上限 8s / 6s），
  不再固定等 6s + 5s；备忘录只在文件中心拿不到发票时才查，且**每个 TK 只查一次**
  （缓存给同 TK 后续行直用——多供应商共票的后继行不再访问任何页面）。
- 经验速度：**约 6~10 秒/TK**，200 行级别整份 **20~40 分钟**（网络慢会更久）。
- 给 WorkBuddy 的指令要**一口气跑完**：一次 `--yes` 全量，不要 `--limit` 分批、不要
  逐行停顿解读；跑批中途的逐行 `[i/N] …` 输出是正常进度，不是卡死。
