# 录入口径参考（confirm-TK 结算邮件 → 多维表）

> AI 回答业务「这列为什么是这个值 / 这行为什么异常」之前先读完本文。
> 口径由管理员方维护（2026-11-05 与业务定版），业务如需改口径请找管理员，勿自行改代码。

## 触发条件

- 邮箱：`.env` 里 `MAIL_USER_MAILBOX_ID` 指定的用户邮箱，收件箱（INBOX）
- 只录**主题或正文（base64 解码后）含 "confirm"（大小写不敏感）**的邮件
  ——真实结算邮件主题形如 `Fw: Invoice 1004 from …`，`Confirmed.` 在正文里

## 行结构（无层级）

每个 TK 一行；邮件级字段（日期/主题/收件人/发票金额/发票识别字段/发票附件/异常报错）
**每行全量填满**，便于按行筛选、核对、导出。表内一行 ≠ 一封邮件，一封邮件通常产生多行。

## 各列来源

| 列 | 来源 |
|---|---|
| 收到邮件日期 | 邮件时间 |
| 邮件主题 | 原样 |
| 收件人邮箱号 | 收件人地址（首位） |
| TK号 / 数量 | 正文「柜号 TK-xxxxxxxx 数量」行（柜号不录入）；空白/NBSP/制表符分隔，跨行或整段一行均可；同 TK 多次出现数量累加；**TK 后不带数量时默认 1 单** |
| 发票金额 | 正文金额（关键词行 Total/Amount/合计… > 货币前缀 CAD/$… > 全文唯一金额）；正文没有时**回退发票 PDF** 的 Balance Due/Total |
| 摊分金额 | 发票金额 × 数量 ÷ 总数量，round 2 位，尾差补到最大行（Σ摊分=发票金额）；**邮件全都不带数量时=多单平摊（AA），单 TK 无数量=全额**，混排时缺数量的按 1 计加权 |
| 服务商名称 / 我司名称 | 发票 PDF：抬头首行（单字母合并 A B C→ABC）/ BILL TO 下一行 |
| 发票币种 | 发票 PDF：CURRENCY 块 > 金额旁币种码 > `$` 金额+GST/HST 加拿大信号→CAD |
| 开票日期 / 发票DUE date | 发票 PDF：`DATE`（排除 DUE DATE）；MM/DD 优先，月>12 回退 DD/MM |
| 发票名称 | 与「发票」列附件文件名一致（如 `Invoice_1002_from_A_B_C_Logistics.pdf`） |
| 发票号 | PDF：`INVOICE 1001`→1001；`Invoice No. INV-100001`→INV-100001 |
| 发票 | 同名邮件（含本封）的非内嵌附件，按文件名去重后全部挂上 |
| 异常报错 | 见下节 |
| 费用项-结算手动提供 | **留空，人工填**（工具永不自动填） |
| 消息ID | 系统幂等列（视图隐藏即可）；rebuild-state 靠它恢复游标，勿删 |

## 异常报错列（设计行为，落表 ≠ 故障）

解析不出的邮件不丢弃，以异常行落表由人工补：

- **未识别TK行**——正文没有「TK号+数量」结构
- **未识别发票金额**——正文和 PDF 都找不到金额
- **同名邮件无附件**——confirm 邮件与带 PDF 的转发间隔几秒先后到达，
  同步正好夹在中间（罕见；watch 5 分钟窗口下两封几乎总在同轮）
- **附件下载失败**——可下轮重试类

## 防重设计

- 同主题组内「有 TK 行的最早一封」=业务邮件；TK 行完全一致的转发与纯附件转发
  只当附件来源，不重复录入
- 整组无 TK 行才落一行异常
- 本机去重游标在 `data\state.json`；换机/重装后先 `rebuild-state`（从表内消息ID列重建）

## 归档（archive 命令）

- `archive` 只把**已写入表**的结算组邮件从收件箱移到归档文件夹（ARCHIVED），
  是邮箱整理动作：表和去重游标都不变，误操作去邮箱「Archived」里移回即可。
- 安全规则：只动「收件箱可见 + 本机已处理 + 所在主题组已写入表」的邮件；
  未处理完的组、异常待人工的组、与本工具无关的普通邮件一律不动。
- 各组里若有附件转发与业务邮件主题不完全一致，会被保守留在收件箱（宁可漏归不误动）。

## 历史遗留备注（业务可能问起）

- **邮件正文金额与 PDF 附件金额不一致**：少数发票存在两版金额（邮件引用版与 PDF 附件版
  本身不同）。当前口径是**按邮件正文金额录入**；遇到差额追问不要自行改表，让业务找管理员
  拍板处理。
- 不同供应商的邮件格式差异已适配；新供应商格式变化会以异常报错列体现，属正常兜底。
