# 应用申请指引（业务自己申请企业自建应用，一次性）

> 目标：你自己名下申请一个企业自建应用，拿到 **App ID（cli_ 开头）** 和 **App Secret** 填进 `.env`。
> 同一个应用既读你的邮箱、又写结算多维表，不需要申请第二个。
> 全程约 15-30 分钟；其中**两步必须管理员操作**（审批应用发布、把应用加为多维表文档应用），其余你自己完成。
> 可以让 AI（WorkBuddy）带着做——直接对它说「按 应用申请指引.md 带我申请应用」。

## 第 1 步：创建应用

1. 浏览器打开 <https://open.larksuite.com>，用你的 Lark 账号登录，进入
   **开发者后台（Developer Console）**。
   - 若提示无权创建应用：租户限制了创建人，找管理员给你开通开发者权限后重来。
2. **创建企业自建应用（Create custom app）**：
   名称如 `lark-mail-sync-你的名字`，描述随意（"结算邮件自动录入"），图标默认。
3. 进入应用 → **凭证与基础信息（App credentials）** 页面，抄下两样：
   - **App ID**（`cli_` 开头）→ 之后填 `.env` 的 `LARK_APP_ID`
   - **App Secret** → 填 `LARK_APP_SECRET`（只显示一次；没抄到就点「重置」重新拿，
     重置后旧 Secret 立即作废，`.env` 要同步改）
4. 左侧「**应用能力 / App capabilities**」→「添加应用能力」→ 选「**机器人 / Bot**」→ 启用。
   ⚠ 不开的话第 5 步管理员在「添加文档应用」里**搜不到**你的应用；若提示要发布版本才生效，
   跟第 3 步合并发布即可。

## 第 2 步：开通权限（权限管理 / Permissions）

在「权限管理」的搜索框里**整串粘贴**权限名，勾选并开通**以下 6 个**（缺一个功能就不完整，
见下方用途列；权限名可以整串一起粘进搜索框逐个搜）：

| 搜索关键词（整串粘贴） | 权限显示名 | 它是干什么用的 |
|---|---|---|
| `mail:user_mailbox.message:readonly` | 读取用户邮箱邮件 | 列出邮件、读邮件详情、拿附件下载链接（附件内容用它下载） |
| `mail:user_mailbox.message.subject:read` | 获取邮件主题 | 读邮件标题（不开=标题返回空、静默失败） |
| `mail:user_mailbox.message.body:read` | 获取邮件正文 | 读正文里的 TK 号和金额（不开=正文返回空、同步总说「无待处理」） |
| `mail:user_mailbox.folder:read` | 查询邮箱文件夹 | 自检、归档时确认文件夹 |
| `mail:user_mailbox.message:modify` | 修改邮件 | 归档：把处理完的邮件移入归档文件夹 |
| `bitable:app` | 多维表格 | 把解析好的结算数据写进多维表、把发票 PDF 作为附件上传（上传附件也用它，**不需要**另开 drive:file） |

> ⚠ 最常见的坑：只开了第 1 个 `readonly` 就以为够了——主题/正文是独立权限，不开的话
> 接口不报错但返回空，表现为「同步总说无待处理」。6 个开齐再进第 3 步。

## 第 3 步：发布应用（⚠ 管理员审批，权限发布后才生效）

1. 左侧「版本管理与发布（Version management）」→ 创建版本 → 版本号 `1.0.0`、
   更新说明随意 → **申请发布**。
2. 通知管理员在管理后台**审批通过**。
3. ⚠ 没发布（或未通过）= 权限不生效，自检必失败——这是最常见的卡点。

## 第 4 步：可用范围（把你自己加进去）

应用管理 → 本应用 → **可用范围（Availability）** → 添加 → 选你自己（或你所在部门）。

⚠ 漏了这步，自检会报 `99991672 缺权限`——不是工具坏了，也不用重装。

## 第 5 步：把应用加为多维表的文档应用（⚠ 管理员/表主人操作，一次性）

1. 把你的 **App ID 或应用名**发给管理员。
2. 管理员在结算多维表里：右上角「**…**」→「**添加文档应用 / Add document app**」→
   搜索你的应用 → 权限选「**可编辑**」。
3. 每个业务各加各的应用；管理员对每个应用只做这一次。

## 第 6 步：填 .env 并自检

| `.env` 键 | 填什么 |
|---|---|
| `LARK_APP_ID` / `LARK_APP_SECRET` | 第 1 步抄的你自己应用的凭证 |
| `MAIL_USER_MAILBOX_ID` | 你自己的邮箱地址 |
| `BITABLE_APP_TOKEN` / `BITABLE_TABLE_ID` | 管理员发的**表信息**（不是凭证，明文发没问题） |
| `BITABLE_APP_ID` / `BITABLE_APP_SECRET` | **留空**（同一应用既读邮件又写表） |

然后对 AI 说「做一次环境自检」（probe）。四行全过 = 申请完成，可以正式使用。

## 常见卡点速查

| 现象 | 原因 | 解法 |
|---|---|---|
| 开发者后台进不去 / 不能建应用 | 租户限制了谁可创建 | 找管理员开开发者权限 |
| probe 报 `99991672` 缺权限 | 权限没发布，或可用范围没加自己 | 完成第 3、4 步 |
| probe 多维表失败（403/权限类） | 应用没被加为该表文档应用 | 完成第 5 步 |
| 添加文档应用里搜不到自己的应用 | 应用还没发布通过，或第 1 步没加「机器人」能力 | 先完成第 3 步；再回第 1 步第 4 点确认已加机器人能力 |
| App Secret 填了不生效 | 重置过没同步改 `.env` | 重抄一次填入 |
| 同步总说「无待处理」但邮箱里明明有结算邮件 | 6 个权限没开齐（常见漏了主题/正文读取） | 回第 2 步补齐，再重新发布一次（第 3 步） |
| 归档报权限/403 类错误 | 没开 `mail:user_mailbox.message:modify` | 回第 2 步补开并重新发布 |
